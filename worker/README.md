# cFlow worker

Temporal worker of [cFlow](https://github.com/fernandomarcius/cflow). It runs everything that must
not live inside an API request:

- **Pipeline execution**: `ExecutarPipeline` (one pipeline = a graph of nodes, one activity per
  node) and `ExecutarDAG` (a chain of pipelines that depend on each other), on the
  `cflow-execucao` task queue.
- **External ingestion**: `IngerirFonte` (one run = N slices, one activity per slice) on its own
  `cflow-ingestao` queue, so a large backfill never delays pipeline runs.
- **Reports**: `GerarRelatorio` (one export = one activity) on the `cflow-relatorios` queue.
- **Schedulers (ticks)**: the pipeline scheduler, the ingestion cadence and the orphan-run reaper.
  They run in every replica; database locks make that safe. Set `CFLOW_WORKER_TICKS=false` on
  replicas that should only run activities.
- **Health probe**: `GET /healthz` on `CFLOW_HEALTHZ_PORTA` (default 8080, `0` disables). It answers
  200 only while the workers are polling and the Temporal frontend is reachable. SIGTERM/SIGINT drain
  the process (`CFLOW_WORKER_DRENAGEM_SEGUNDOS`, default 20 s) before exiting.

All business logic lives in the shared core (`../core`, package `cflow_core`); this package only wires
it to Temporal. Module and function names are in Portuguese, matching the core.

## Layout

```
src/cflow_worker/
  main.py                  process wiring, tick loops, graceful drain
  workflow.py              ExecutarPipeline / ExecutarDAG
  activities.py            executar_no_act / finalizar_act
  ingestao_workflow.py     IngerirFonte
  ingestao_activities.py   slice activities
  relatorios_workflow.py   GerarRelatorio
  relatorios_activities.py report activity
  saude.py                 /healthz probe
tests/                     unit tests + Temporal replay tests (no database, network or server needed)
```

## Develop

The worker depends on the core by path (`cflow-core @ ../core`, editable), so work from a checkout of
the whole repository:

```bash
cd worker
uv sync
uv run pytest
uv run ruff check src tests
uv run python -m cflow_worker.main      # needs CFLOW_DATABASE_URL, CFLOW_TEMPORAL_HOST, ...
```

Configuration is read by `cflow_core.config` (environment variables with the `CFLOW_` prefix).

### Replay tests

`tests/replay/historicos/*.json` are recorded Temporal histories. `tests/replay/test_replay.py`
re-executes them with the current workflow code: any change to the command sequence of a workflow
must be protected with `workflow.patched`, otherwise in-flight runs would fail with a
non-determinism error after a deploy. Histories are generated by `tests/replay/gerar_historicos.py`
(do not regenerate them just to make a test pass).

## Docker

The image bundles the .NET SDK for the C# code node. The build context is the repository root:

```bash
docker build -f worker/Dockerfile -t ghcr.io/fernandomarcius/cflow-worker .
```
